# 建档手册 · onboarding

## 目的

为新用户完成一次全面但零压力的信息梳理，建立个人档案。原则：**强问项只有 3 个，其余全部可选**。用户答不上来、不想答的，直接跳过并在档案里标「未提供」，不影响后续任何流程。

## 一、提问顺序与清单

### 强问项（缺了没法开工，逐个确认）

1. **当前体重**：大概数值即可，精确到 0.1kg 更好。顺带确认体重秤的测量习惯（空腹 / 随意、每天 / 偶尔）——这决定后续数据点怎么解读。
2. **主要目标**：减脂 / 增肌 / 体成分重组（同时增肌减脂）/ 体能与运动表现 / 保持健康。目标决定后续所有判断口径（见 analysis-rules.md「目标决定判据」）。
3. **训练经验**：练了几年、练过什么（力量训练 / 跑步 / 球类 / 完全零基础）。零基础和新手要提示安全红线更严格。

### 可选项（按话题分组，每回合 3 问，用户没提到的下次再问，不追）

| 分组 | 问题 |
|:--|:--|
| 身体 | 身高、年龄；体脂率（有没有测过、用什么工具）；体重之外还想追踪什么 |
| 健康 | 有没有已知的伤病史或慢性问题；最近有没有持续疼痛或麻木；睡眠大致怎么样 |
| 训练 | 每周大概练几次；偏好的动作或项目；训练场所与可用器械（健身房 / 居家 / 特定运动场馆） |
| 生活 | 饮食大致模式（是否规律、有无聚餐应酬习惯）；饮酒习惯；咖啡因摄入习惯 |
| 追踪偏好 | 手上用什么训练 APP（有没有截图可解析）；打算多久做一次复盘；可视化报告想看哪些维度 |

### 记录节奏（低频原生的关键一问）

问用户「打算多久记录一次——每天、每周、还是想起来再记？」。这条问的**不是承诺，是预期管理**：

- 答案只写进档案（「记录节奏」字段），**不产生任何 KPI**，不构成承诺，不复盘时对照考核
- 无论用户答什么，都补一句定心话：「多久记一次都行，技能按低频设计——一次补几周的数据也可以，记录到的就是全部事实」
- 用户说「随缘」→ 记「随缘」，这是最常见也完全健康的答案

### 维度开关（建档最后一问）

向用户确认以下维度中**哪些打算持续提供数据**，结果写进档案，后续流程按开关执行：

- 体重（默认开）/ 体脂 / 肌肉量 / 睡眠 / 酒精 / 饮食 / 主观体感评分

用户只选体重 + 训练 → 完全成立，后续复盘与可视化照样完整可用，只是相关图表自动隐藏。

## 二、档案落盘格式

写入 `fitness-data/profile.md`：

```markdown
# 个人档案

**建档日期**：YYYY-MM-DD
**数据目录**：fitness-data/（与用户确认过的位置）

## 基础信息
- 身高 / 年龄：
- 起始体重：
- 起始体脂：（未提供则写「未测」）
- 主要目标：（含目标数值与期限，用户给了就记，没给就写「未定，后续补充」）

## 训练背景
- 训练经验：
- 每周频率（现状 / 期望）：
- 训练场所与器械：
- 偏好动作 / 项目：

## 健康与安全
- 伤病史 / 慢性问题：
- 当前疼痛或麻木：
- 安全红线：（从 analysis-rules.md 摘录刺痛/发麻/酸胀三级，默认全部生效）

## 生活习惯
- 饮食模式：
- 饮酒习惯：
- 咖啡因：

## 追踪设置
- 维度开关：体重 ✅ / 体脂 ⬜ / 肌肉量 ⬜ / 睡眠 ⬜ / 酒精 ⬜ / 饮食 ⬜ / 主观评分 ⬜
- 记录节奏：（用户自述，仅作预期参考，不构成承诺）
- 训练 APP 截图：（有 / 无；有则记录 APP 名称）
- 单位习惯：（记录用户用什么单位体系，如「哑铃 kg、缆绳 lbs」或「全部 kg」——写入后在 data-collection 环节校验用）

## 备注与约定
- （用户在建档时说过的任何特殊要求，逐条记录）
```

## 三、建档后必做

1. 初始化三张 CSV（只写表头行，不写任何数据行）：
   - `measurements.csv`：`date,weight_kg,bodyfat_pct,muscle_kg,sleep_h,sleep_score,alcohol_std,notes`
   - `sessions.csv`：`date,type,duration_min,total_volume_kg,calories,notes`
   - `exercises.csv`：`date,exercise,sets,reps,weight,unit,side,notes`
2. 创建 `reviews/` 与 `dashboards/` 两个子目录
3. 若用户当场就有数据（比如刚练完），顺势做第一次记录，让用户立刻看到数据落盘的效果
4. 告诉用户下次的触发方式：「下次直接说『记录一次训练』或『做周复盘』就行」

## 四、建档禁忌

- ❌ 不要一次性抛出全部问题——按强问项 → 分组可选项的顺序，每回合 3 问
- ❌ 用户没提供的数据不要留空字段就完事——档案里显式写「未提供」，让后续会话知道是「没问过」还是「问过没有」
- ❌ 不要在档案里写任何评价（「体脂偏高」之类）——档案是事实记录，评价留给复盘
- ❌ 目标未定的用户不要硬塞一个 SMART 目标——记「未定」，复盘跑两轮后自然会浮现
