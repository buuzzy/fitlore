# 数据收集手册 · data-collection

## 四种入口

用户随时会以下列方式交数据，处理方式不同，落盘格式相同（三张 CSV）：

1. **训练 APP 截图**（立即处理，见第二节 SOP）
2. **口述 / 手动输入**（直接解析，见第三节）
3. **批量补录**（多张截图 + 口述一起交，低频用户的标准姿势，见第四节）
4. **训练 APP 导出 CSV 导入**（最省力的入口，见第五节）

收到数据后当场解析、当场追加 CSV、当场回报记录结果，**不要等下一次复盘**——临时数据最容易被遗忘或丢失。

## 一、落盘格式（三张 CSV）

| 文件 | 粒度 | 列 |
|:--|:--|:--|
| `sessions.csv` | 每次训练一行 | `date,type,duration_min,total_volume_kg,calories,notes` |
| `exercises.csv` | 每个动作一行（同一动作多组可合并记一行，reps 记「8×4」形式） | `date,exercise,sets,reps,weight,unit,side,notes` |
| `measurements.csv` | 每次测量一行 | `date,weight_kg,bodyfat_pct,muscle_kg,sleep_h,sleep_score,alcohol_std,notes` |

**写入规则**：
- 只追加，不改历史行
- 缺失列留空，不填 0——0 和未追踪是两回事
- 日期格式统一 `YYYY-MM-DD`
- `type` 用用户自己的叫法（推拉腿 / 上下肢 / 跑步 / 攀岩……），不做强行标准化
- `alcohol_std` 记标准drink数（1 个标准drink ≈ 14g 纯酒精 ≈ 1 罐 330ml 啤酒 ≈ 50ml 52° 白酒的 40%），换算有疑问时先问用户、在 notes 里记原话
- 一次记录涉及同一天多个文件时，全部写完再回报

## 二、截图解析 SOP

### 解析步骤

1. **先找日期**：截图顶部的日期是唯一权威。用户口述的日期与截图冲突时以截图为准，并提醒用户
2. **提取场次级数据**：总时长、总容量（或总重量）、消耗大卡——写 `sessions.csv`
3. **提取动作明细**：动作名 / 组数 × 次数 × 重量——写 `exercises.csv`，一行一个动作
4. **标记单侧动作**：动作名含「单臂 / 单侧 / 交替」或明显单侧模式时，`side` 列填 L / R / LR
5. **心率区间异常**（如有）：不在 CSV 里体现，口头提醒用户或在 notes 里带一句
6. **容量校验**：截图给了总容量就直接用；没给则用 Σ(组数 × 次数 × 重量) 估算，notes 标「估算」

### 单位与口径校验（最容易出错的一步，每次解析必做）

- **照搬截图原文单位**，不要擅自换算或统一
- **同场次同类器械的单位必须一致**：同一天既有哑铃动作又有缆绳动作时，逐个核对单位——发现同类动作单位不一致，先怀疑记录错误，向用户确认后再落盘
- **数字离谱时先怀疑单位**：按用户档案里的「单位习惯」反推合理性（例：缆绳按 lbs 读是 45kg 拉力属正常，按 kg 读成 100kg 拉一下就是世界级水平——显然是单位问题）
- **单双侧辨别**：「重量轻 + 次数翻倍」是单侧模式的正常特征，不要判成退步。单侧动作的重量通常是双侧的一半左右
- **口径不同不比较**：同一动作的历史记录若存在单侧 / 双侧口径差异，两条记录**不可直接对比**，必须先换算成同口径或在图表里分开呈现。这是所有分析错误里最常见的一种

### 解析后必做

把解析结果用一张小表回报给用户（动作 / 组数次数重量 / 备注），确认无误后说明「已记录」。用户当场指出错误 → 以正确值重新追加一行并在 notes 里注明「更正 YYYY-MM-DD 原记录」，**不删旧行**。

## 三、口述记录处理

用户口述通常不完整，按此优先级解析：

1. **日期**：没说就问一句「是今天的训练吗」
2. **动作与组次重**：核心必记项。用户只说「卧推 60 做了 8 个」→ sets 记 1，notes 不编组数
3. **体感**：顺势问一句「今天练完感觉怎么样」——是本技能的核心互动点（见 review-workflow.md 的体感分级），但只问一次，用户不想展开就过
4. **体重等测量值**：用户顺口提到就记，没提不追问（复盘时统一问）

## 四、批量补录（低频用户的标准姿势）

低频用户最常见的形态：两三周记一次，一次交来多张截图 + 几句口述。这是本技能的一等公民流程，处理规范：

1. **先收全、再动手**：把用户这一批的截图和口述全部收集齐，列一张清单回报（日期 + 类型 + 一句话内容），确认没有遗漏再开始解析——避免解析到一半用户又补图
2. **按日期归位**：每张截图独立解析，数据写入对应日期的行；口述内容归属到用户说的日期，没说日期的逐条确认
3. **跨周合并出复盘**：批量补录通常伴随「把这段也盘一下」的诉求——补录完成后主动询问是否做一次「盘最近」，一份复盘覆盖整个区间，不按周拆分
4. **缺的周次不追责**：区间内完全没有记录的周，复盘里一句「未记录」带过，不展开分析、不评价、不提醒用户「你断更了」
5. **同一区间已有部分记录时**：先读 CSV 里该区间已有的行，新数据只补缺口，重复的场次向用户确认是否覆盖（覆盖按回改留痕规则走）

## 五、外部文件导入（Skill 只管数据契约，格式解析交给 Agent）

用户可能直接丢过来训练 APP 导出的表格文件（Hevy、Strong、训记或任何来源）。**解析具体格式是 Agent 框架与模型自身的能力，不属于本技能**——本技能不写任何 APP 的列名映射与导出路径，只约定三条数据契约，保证无论什么格式进来的数据，落盘后口径一致：

1. **先看样本再动手**：读文件头与两三行样本，向用户确认列含义与单位口径（列名带单位后缀以列名为准；不带时按档案「单位习惯」判断，拿不准就问）
2. **批量转换必须用脚本**（SKILL.md 算术铁律）：逐行转写进三张 CSV，不手敲、不心算
3. **先回报、再落盘**：转换完成后报告覆盖日期区间、场次总数、动作数、发现的异常行（日期倒序、单位混用、重复行），用户确认后再写入；历史数据与新记录口径不一致时在 notes 里标注口径，不静默换算

## 六、测量数据记录（measurements）

- 体重：记录时在 notes 里带测量条件（空腹 / 餐后 / 晨起），后续对比只做同条件对比
- 体脂：家用体脂秤的绝对值不稳定，**趋势比单点可信**；换秤、换电池后读数跳变要记入 notes
- 睡眠：手表数据（时长 / 深睡占比）与主观分分开记；没有手表就只记主观 1-10 分
- 维度开关里没开的维度，即使用户随口提到也不主动建档追踪——避免数据残缺反而引发误判

## 七、数据纠错与回改留痕

发现已落盘的数据有错（读错截图、单位错、日期错）时：

1. **CSV**：追加一行正确值，notes 列写「更正 YYYY-MM-DD，原记录 XX 有误」；不删不改旧行
2. **复盘文档**：若错误已进入复盘叙述，按三件事处理——保留原文可见（删除线）、顶部写回改说明、同步所有引用该数据的段落
3. **可视化**：受影响的图表重新生成，旧 HTML 保留（历史快照有价值）

理由：历史记录的价值一半在「当时记了什么」，一半在「当时怎么判断的」。直接覆盖会把认知修正的线索一起抹掉。
