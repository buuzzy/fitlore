# 复盘工作流 · review-workflow

## 复盘的本质

复盘不是数据汇报，而是一次**对话**：AI 用结构化的问题帮用户回忆和梳理这一段时间的训练与身体状态，把散落的信息变成一份可追溯的文档，再用图表让用户直观看到变化。用户的参与度有高有低，流程必须两头都能跑：愿意聊就按提问规范充分互动，不想聊就只靠已有数据 + 一句话总结。

## 一、盘最近流程（核心复盘，7 步）

**这是本技能的标准复盘形态，时间无关**：输入是「自上次复盘以来的全部记录」，不按日历周期切分。用户可能三天来盘一次，也可能五周来盘一次——流程完全相同。周复盘、月复盘只是它的归档变体。

1. **读上下文**：`profile.md`（维度开关、目标、记录节奏）→ 最近一份复盘 → 自该复盘日期以来新追加的全部 CSV 行
2. **收数据**：先看 CSV 里这段区间已有多少——已有数据直接用，缺什么在提问环节补问；用户带着一批截图来 → 先走批量补录（data-collection.md 第四节）再复盘
3. **对话式提问**：按第五节的引导问题清单，每回合 3 问，聊到用户喊停；提问全部用「最近 / 上次聊完到现在」，不用「这周」
4. **写复盘文档**：`reviews/YYYY-MM-NN.md`（NN 为当月序号，01 起），模板见第三节
5. **补录 CSV**：对话中获得的测量值（体重、睡眠等）当场追加 `measurements.csv`
6. **生成/更新可视化**：询问用户是否生成当月可视化报告（visualization.md）
7. **定下次重点**：一条就够，写进复盘文档末尾，下次复盘开头先回收

**断更处理**：距上次复盘间隔很长时，第一句话是欢迎（「好久没盘，先把你这批记录收了」），区间内无记录的周次在文档里一句「未记录」带过——不追责、不分析空白、不提醒打卡。

### 周次与日期陷阱

- **项目周次口径 = 用户自己的周一定义**。ISO 周号、用户口径、文档里的「周几」标注三者可能不一致——**一律先用日历核实真实日期再写周几**，冲突时以日期为准
- 文档里已存在的「周几」标注不可信，引用前先核对

## 二、月度归档复盘（可选变体）

若用户希望按月看一次全景（或当月盘最近的次数 ≥3 次，可主动提议）：

1. 汇总当月所有「盘最近」文档 + CSV 数据
2. 写 `reviews/YYYY-MM-99.md`（序号 99 保留给月度归档），模板见第四节
3. **必做**：生成当月可视化报告（visualization.md），这是月度归档的核心交付物
4. 目标进度检查：若档案里有带期限的目标，算一次完成度；没有目标就只看趋势

## 三、盘最近文档模板

```markdown
# 复盘 · YYYY-MM-NN（MM-DD ~ MM-DD，自上次复盘以来）

**总结论**：一句话判断 + 这段区间最重要的一个事实。

---

## 一、关键数据
| 指标 | 上次对比点 | 本次 | 变化 |
（只列维度开关里已开的指标 + 训练数据；对比用「本次 vs 上一次记录」，
缺数据标「未追踪」；数据点稀疏时注明「点少，只谈方向」）

## 二、训练详情
（按日期排列每个训练日一小节：日期 · 类型 · 时长 / 容量；动作表来自 exercises.csv；
用 ⭐ 标突破、✅ 标亮点、⚠️ 标不足；区间内未记录的周次一句「未记录」带过）

## 三、体感与状态
（疼痛 / 酸胀 / 疲劳 / 主观感受，对话中收集；全部可选）

## 四、饮食与睡眠
（维度开关已开才写；睡眠含客观数据与主观分）

## 五、三个最有效的事
## 六、三个最不该的事
（对偶约束：五、六必须能两两呼应——每条「最有效」都有一条「最不该」反例，
避免写成流水账。数据不足以各凑三条时写实际条数，不硬凑）

## 七、下周调整
（1-2 条可执行项，下次复盘回收）
```


## 五、引导问题清单（盘最近用）

**提问格式（硬规则）**：
- 每回合 3 个问题，每问带背景 / 原因 / 目的，挤在 1 段话里
- 回答空 → 标「未追踪」，不追问第二次
- 用户只想快速过 → 最少问 Q1、Q2、Q3

按优先级排序（前 3 个是底线问题；所有「本周」类措辞替换为「上次聊完到现在」）：

1. **这段时间哪几天训练了？**（背景：CSV 可能只有零散记录，出勤是所有分析的地基）
2. **有没有训练截图或想补记的数据？**（背景：临时数据最容易漏交，漏了这段就残缺）
3. **有没有新重量 / 新次数 / 新动作？**（背景：突破是复盘的亮点锚点，也是单位口径校验的时机）
4. **体重称了吗？最近一次多少？**（维度开关已开才问；一次数据点即有效）
5. **体感怎么样——有没有哪里酸胀或刺痛？**（背景：疼痛分级决定后续是否调整，见 analysis-rules.md）
6. **训练感受舒服吗？**（背景：舒服 = 可持续；持续不舒服的计划迟早被弃）
7. **睡眠怎么样？**（维度开关已开才问；主观 1-10 分即可）
8. **饮食 / 酒精有没有特别的日子？**（维度开关已开才问；只问「特别的」，日常不追）
9. **上次定的调整项做到了吗？**（回收上次复盘第七节）

## 六、体感与疼痛分级（复盘必核，日常记录也适用）

| 信号 | 判定 | 处置 |
|:--|:--|:--|
| 肌肉酸胀、训练后延迟酸痛 | 正常 | 继续，无需调整 |
| 酸胀发紧（关节 / 肌腱处） | 警告 | 可完成当前组，下次不加重，观察 |
| 尖锐刺痛（当场） | 红线 | 立即停，当天不再练该部位 |
| 手臂发麻 / 神经信号 | 红线 | 立即放弃该动作，复盘时单独记录 |
| 隐痛持续 24h+ | 红线 | 下次训练减量 50%，72h 不消退建议就医 |

体感问题的问法：**先问部位、再问性质（酸 / 紧 / 刺痛 / 麻）、最后问持续时间**——直接问「疼不疼」得到的信息量很低。

## 七、复盘禁忌

- ❌ 不把中断训练（有事 / 疲惫）解读为态度问题——只有用户自己说是偷懒才算
- ❌ 遇到异常数据（消耗量比同类训练低一个数量级之类）先怀疑记录完整性，再谈训练质量
- ❌ 不写「计划执行率」这类没人填得对的指标——记录到的就是真实数据
- ❌ 不在复盘里堆全部历史数据——对比只用「本次 vs 上一个可对比点」，更早的交给可视化报告
- ❌ 周期化的执念：不要按「周」切分析单元——输入区间就是「上次复盘到今天」，区间里几个周无关紧要
- ❌ 复盘写完不更新 CSV、不复核图表数据 → 下次复盘会读到不一致的版本
