# 可视化手册 · visualization

## 目标

把 CSV 里的数字变成一张用户「扫一眼就看到变化」的报告：自包含 HTML，图表库与数据全部内嵌，**双击即可在浏览器打开**，不需要服务器、不需要网络。这是月度归档的核心交付物，「盘最近」复盘按需生成。

低频用户的可视化策略：**大跨度对比优先**。数据稀疏时，单周粒度的图没有信息量，真正打动用户的是「三个月卧推从 60 到 70」这种大区间变化——动作进步图和体重趋势天然支持大跨度展示，优先保证这两张图的质量。数据点稀疏时在图上方显式标注「数据点较少，图中连线仅示意方向，不代表逐日变化」。

## 一、构建方式（一条命令）

数据和模板都已备齐，构建只需两步：

1. 从三张 CSV 汇总出数据 JSON（结构见第三节），保存为临时文件（如 `fitness-data/dashboards/.data.json`）
2. 执行构建脚本：

```bash
python3 <技能目录>/assets/build_dashboard.py --data <数据json> --out fitness-data/dashboards/YYYY-MM.html
```

脚本会把 ECharts 与数据注入模板，输出自包含 HTML（约 1MB），并自动做注入自检。**不要手工编辑生成的 HTML**——要改图表样式就改模板，再重新构建。

## 二、图表板块与降级规则

模板按数据有无自动显隐，规则如下：

| 板块 | 数据要求 | 无数据时 |
|:--|:--|:--|
| 指标卡（体重变化 / 体脂变化 / 累计训练次数 / 累计容量） | 各自独立判断 | 该卡隐藏 |
| 体重 / 体脂趋势线 | 至少 1 个测量点 | 整块隐藏 |
| 周训练频率与容量 | sessions 数据存在 | 整块隐藏 |
| 动作重量进步 | 至少 1 个动作有记录 | 整块隐藏 |
| 睡眠 | sleep_h 或 sleep_score 存在 | 整块隐藏 |
| 备注 | notes 非空 | 整块隐藏 |

**最小可用场景**：用户只有体重 + 训练数据 → 报告仍然完整成立（3 张指标卡 + 体重趋势 + 周训练图 + 动作进步图），这正是最常见的真实情况，不要因为缺维度就觉得「报告不完整」。

**单点数据**：只有 1 个体重点时，指标卡显示单点值并注明「暂无趋势」，趋势图照画（会以孤立点呈现）——诚实显示，比隐藏好。

## 三、数据 JSON 结构

```json
{
  "user": "用户名（可空）",
  "title": "2026-10 月度复盘 · 数据可视化",
  "period": "2026-08-01 ~ 2026-10-17",
  "generated_at": "2026-10-18",
  "notes": ["长假停训一周", "10-12 起执行新计划"],
  "measurements": [
    {"date": "2026-08-02", "weight_kg": 79.8, "bodyfat_pct": null, "sleep_h": null, "sleep_score": null}
  ],
  "weeks": [
    {"week": "W32", "sessions": 3, "volume_kg": 18200, "duration_min": 190}
  ],
  "exercises": [
    {"name": "卧推", "unit": "kg", "points": [{"date": "2026-08-03", "weight": 60, "reps": 8}]}
  ]
}
```

### 汇总规则

- `measurements`：直接来自 `measurements.csv` 的行，缺的列填 null
- `weeks`：按周汇总 `sessions.csv`，volume 来自 total_volume_kg 求和；周次口径与用户复盘一致（reviews 文件名里的 Wxx）
- `exercises`：来自 `exercises.csv`。**取每个动作当日最大重量**（同日多组取最重一组的重量）；reps 记录对应那组的次数。单位保持原样，**不同单位体系绝不合并**
- `exercises.points` 数量控制在每个动作 ≤ 20 个点，超过时按时间均匀抽样——图表是看趋势的，不是存档

## 四、选择展示哪些动作

全部动作都画会把图搞乱。优先级：

1. 用户档案里的偏好/主项动作（建档时问过）
2. 记录次数最多的前 5 个动作
3. 用户点名想看的动作

其余动作留在 CSV 里，用户想看随时能加。单位不同的动作会自动分图，向用户说明「不同单位不可跨图对比」。

## 五、配色与可读性约定（已内置于模板，改动需同步说明）

- 浅色主题：浅灰底 + 白卡片 + 深色文字，保证打印和白天阅读舒适
- 主色蓝，辅助绿 / 琥珀 / 紫；下降用绿、上升用红仅用于「好坏判断明确」的指标（体重变化的涨跌色按目标方向自动着色，不套用股市惯例）
- 每张图都有副标题说明读法（「缺测日期表示未追踪」这类提示直接写在图上方），避免用户把缺数据误读成「没变化」
- 趋势图按 analysis-rules.md 第 10.3 节的密度档位标注：稀疏数据不画速率、不写「每周 X」，副标题写「数据点较少，仅示方向」

## 六、历史快照

- 每月生成的新 HTML **覆盖同名文件**（`YYYY-MM.html`），跨月自然形成时间序列
- 数据回改后重建报告即可，旧报告不保留多版本——历史真相以 CSV 的追加式记录为准，报告只是当时的快照视图
